### 各层实现来源

| 层 | 实现策略 |
|---|---|
| ① Runtime | **复用 dsh**（dsh-base + 自定义 profile `desktop`）。pi-ai 作桥接 provider 增强 pi 前模型层。权限/沙箱用 dsh 的 sandbox/guard |
| ② Chat & Trace | Electron 壳 + 自研前端。Trajectory = 只读渲染 session 事件流；对话/轨迹双 Tab；运行统计条；审批弹窗接 dsh approval policy |

| ⑤ Studio | **全自研**（本方案最大差异化），以 UI 插件形态挂进 ②③，详见第 4 节 |

## 2. 运行域双模式：会话域（默认）+ 项目域（可选）

这是对 dsh 默认行为最重要的改造。dsh/Claude Code 是"项目制"：启动即指向工作区、扫描目录、加载 AGENTS.md 与 skill。你要的是"会话制"（ChatGPT 式）。建议**不做二选一，做双模式**：

### 2.1 会话域 Session Mode（默认）
- 新建会话 = **空上下文**：不扫盘、不加载项目规则、不注册文件系统工具（或注册但未激活）。
- 每个会话一个 Cordis **isolate 作用域**：挂载的工具集、模型、规则互不串味。
- 模型、技能、文件访问都在**会话设置**里显式配置：
  - 挂载工作区（0..n 个目录）→ 挂了才激活 fs/terminal 工具
  - 挂载规则文件（AGENTS.md / CLAUDE.md / 自定义）→ 显式勾选才进上下文
  - 开启哪些 skill → 渐进披露（pi 式：触发才加载）
- 临时任务、问答、写作、调研——绝大多数场景，零成本开局。

### 2.2 项目域 Project Mode（显式进入）
- 从会话"升级"或从项目入口创建：绑定工作区，自动扫描 + 加载规则（dsh 原生行为）。
- 获得完整 Workbench：文件树、终端、LSP、Git 快照、子代理。
- 适合重构、多日开发、代码库级任务。

### 2.3 双模式切换语义
- 会话 → 项目：挂载工作区 + 激活能力事件域（fs/*）+ 注入项目规则（可预览确认后再注入——上下文透明）。
- 项目内新建子会话：继承项目挂载（子代理场景），但仍是独立 isolate。
- 模式差异在 UI 上只体现为**会话头部的挂载徽章**（如 `📁 2 个工作区 · 3 个技能`），避免两套界面。

**实现落点**：全部在自己的插件里做——一个 `session-scope` 插件用 `ctx.isolate()` 管理每会话作用域，一个 `workspace-mount` 插件控制 fs 工具的激活，不改 dsh 核心。

## 4. Artifacts & Document Studio（路线 A：全自研工作台）

### 4.1 面板显隐机制（你截图的 WorkBuddy 行为）
```
会话事件流 ──→ Studio 触发器插件（监听 capability events）
                ├─ 检测信号：模型 write/edit *.pptx、*.docx、*.html
                │            或调用 ppt/html 生成 skill
                ├─ 发 UI 事件 → 右侧面板滑出 + 工件卡片出现在对话流
                └─ 会话结束后面板可收起；默认状态 = 纯对话
```

### 4.2 各工件类型的实现管线（全部以 HTML 为中间表示）
| 工件 | 生成管线 | 编辑形态 |
|---|---|---|
| **PPT** | 内容 md → 版式模板（design tokens）→ HTML 幻灯片 → 转 PPTX 导出 | **AI 原生幻灯片编辑器**：页面缩略图栏 + 画布 + "选中元素→对话修改"；每个元素绑定语义 token，AI 改版式不破坏内容 |
| **Word/Docs** | 内容 → HTML → DOCX（OpenXML） | 富文本编辑器 + AI 续写/改写选区 |
| **Excel** | 数据 → 工作簿引擎 | 表格组件 + 公式栏 + AI 数据分析 |
| **PDF** | HTML 排版 → PDF（读：解析回 HTML） | 以导出为主，编辑在 HTML 层 |
| **Markdown** | 直接编辑 + 分屏预览 | 双栏 |
| **网页** | HTML/JS/CSS 工件 → iframe 沙箱预览 | **Canvas 双向编辑**：预览区元素点选 → 对话精准改；代码区同步高亮 |
- 工件本身落盘到会话工作区，编辑历史进 session 事件流 → **轨迹里可回放"PPT 第几页第几步怎么改的"**。
- 工件卡片（对话流内）：点击打开右侧 Studio 面板；导出按钮（pptx/docx/pdf/zip）。
- **插件化兜底**：Studio 的每种工件类型都是"工件处理器插件"（注册 mimeType → 渲染器 → 导出器），第三方可扩展新类型（如思维导图、白板）——与第 4 层生态一致。

### 4.3 为什么用 HTML 当中间表示
- 文档/幻灯片/网页三者同源，一套排版引擎（design tokens + CSS）通吃；
- AI 对 HTML 的生成/修改成功率远高于二进制格式；
- 与 WorkBuddy 已验证的 doc-typeset/html-to-docx 管线一致；
- 实时预览零成本（iframe）。

## 6. 风险与对策（汇总）
1. **dsh 破坏性变更**（developer preview）→ 锁版本；自有逻辑全部在自己的插件包；升级只跑适配测试。
2. **Studio 是全新工程**，无整体可复用开源 → 先做 Markdown/网页（简单）再攻 PPT；HTML 中间表示降低难度。
3. **Electron 打包 dsh 运行时**（Node ≥24.9）→ 参考 dsh 官方 desktop 档；Python SDK 侧验证过自带 Node runtime 的先例。
4. **插件树规模失控** → 桌面版 profile 只装必要 bundle（terminal/fs/tools/mcp/skill），其余按需装。
